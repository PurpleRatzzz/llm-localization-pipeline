## Known reference problems

3 of 200 golden references fail the gate themselves (same gate and glossary as the runs). Segment = last 4 digits of the dev id, as in `reports/gate_calibration.md`.

| Segment | Failed checks | First error |
|---|---|---|
| 0392 | protected_content | `Tag <codeph> content changed: "community" missing in target` |
| 0887 | ui_label | `UI label <uicontrol>Debug</uicontrol> must be translated as "调试"` |
| 1539 | tag_nesting | `Tag <uicontrol> inside <menucascade>: source has 2, target has 1` |

- Tag or protected-content errors: broken references (verdicts in `reports/gate_calibration.md`, which ran the same gate on all dev references). A correct translation can disagree with them, so chrF and the QA metrics are unreliable on these segments.

## Method

- **Golden set**: `data/golden.jsonl`, dev segments with professional references. Tagged segments are oversampled to 50% (25.9% in dev), so the overall score over-weights them; chrF tagged and untagged are the per-group scores.
- **chrF**: sacrebleu `nrefs:1|case:mixed|eff:yes|nc:6|nw:0|space:no|version:2.6.0` (character 6-grams, beta 2), corpus level: n-gram counts are summed over the segments, then one F-score is computed. Both sides are normalized first: inline tags removed (their text kept, including code in protected tags), entities decoded (`&lt;` → `<`), Unicode NFKC. NFKC is needed because the references are NFKC-normalized (full-width ，：；（）！？ became half-width in the dataset, style guide R8); without it a correct full-width comma would count as an error. chrF ignores spaces (`space:no`), so CJK-Latin spacing does not change it. Tags are measured by tag integrity instead.
- **Bootstrap**: 1000 resamples of the segments with replacement (seed 42), the same resamples for every run. 95% CI = 2.5th to 97.5th percentile of the resampled corpus chrF. Paired comparison: on each resample, chrF(run) − chrF(baseline); the table gives the observed difference, the 95% CI of the resampled differences, and the share of resamples where the difference is ≤ 0 (an approximate one-sided p-value for "better than the baseline"; resolution 1/1000).
- **QA metrics** re-run the deterministic gate (`check_segment` in `l10n_pipeline/qa_gate.py`, with the glossary) on every final target and ignore the issues stored in the run, so all configurations and the human reference are judged by identical code.
  - *Tag integrity*: tagged segments with no `xml_wellformed`, `tag_set` or `tag_nesting` error. Tag order may change (Chinese word order).
  - *Protected intact*: segments whose source has a `codeph`/`filepath`/`varname` element, with no `protected_content` error. A target that is not well-formed XML counts as not intact, because its protected text cannot be checked.
  - *UI labels*: (segment, glossary label) pairs where the whole text of a `uicontrol`/`parmname` in the source is a "ui" glossary label (`find_ui_labels`); correct = a target tag of the same kind has exactly one of the listed translations (no `ui_label` error).
  - *Terms in text*: (segment, glossary term) pairs where the gate's `find_terms` finds a "text" glossary term in the running text of the source (outside UI and code tags); correct = one of its listed translations appears in the target (no `terminology` error for it).
  - *Gate pass*: segments with no error-level issue. The gate checks format, protected content and glossary terms, not meaning or fluency: it is a routing filter, not a quality score.
- **Routed to review**: share of segments the run itself sent to human review (`status` = `needs_review`): any gate error, plus error-level verifier findings when the verify stage runs.
- **Glossary**: `context/glossary.zh-CN.csv`, 64 entries, 53 required. `target` may list several acceptable translations separated by `|`. Enforced by the gate: required entries, and ambiguous entries that list several options (a closed set). An ambiguous entry with one translation is guidance only ("usually X"). For ambiguous entries the editor double-checks the wording.
- **Cost**: from each run's `summary.json`, computed from the API token counts of every request (a request served from the local cache reports the cost of its original call). $ / 1k words uses the 3,477 source words of the golden set. API seconds = sum of call durations; batches run in parallel, so the wall-clock time is shorter.
- **Human reference** row: the professional translation evaluated as if it were a run: the ceiling for the QA metrics and a sanity check of the glossary. chrF does not apply (it is the reference).
