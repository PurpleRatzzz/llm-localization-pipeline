Gate run on all 2000 dev pairs (EN source, human ZH reference), no glossary. Generated by `scripts/calibrate_gate.py`.

**8 of 2000 references fail the gate** (have at least one error); **2 of those are gate false positives** (0.1% of all references), the rest are broken references.

## Decisions and changes driven by calibration

1. Before the first run, the protected tag set was chosen from the verbatim table above: codeph, varname, filepath. ph (48%), b (57%), userinput (34%) and systemoutput (4/6) are translated too often to be protected.
2. `tag_order` is a warning: re-measured 14/518 tagged references reorder tags. The structural checks are chained (tag_set, then tag_nesting, then tag_order), so the 2 references with a nesting error are not counted again as reorders (14 reorders -> 12 tag_order warnings).
3. `escaped_literals`: severity per entity. `&lt;` 7/7 and `&gt;` 11/11 are kept -> error; `&amp;` is written as 和 in 2/7 references -> warning.
4. `numbers` is a warning: 10 of the 11 references it flags are correct localization. As an error it would fail 8% of the references that contain digits.
5. The data scan found `#URL1#`-style URL masks (42 occurrences in 37 segments, 42/42 kept) and `{!...}` merge fields (4/4 kept). Both were added to the placeholder pattern, and placeholders are removed before counting digits (otherwise #URL1# looks like the number 1).
6. After the first full run (8 references failed: 6 real problems, 2 false positives), codeph and filepath stayed protected. Both false positives (0978, 1352) come from the source tagging prose as code. A false positive costs one human review; a translated identifier ships broken code to readers. A narrower rule (e.g. skip tag texts that contain spaces) would also skip real code such as `CloseDate &lt; TODAY()`.
7. The length message now prints 3 decimals: the first run showed `ratio 0.18 is outside 0.18-1.0` for a ratio of 0.179.
8. The CJK-Latin measurement counts overlapping adjacencies (lookahead), so `中A中` counts 2.

## Not calibrated yet

- `terminology`: the glossary does not exist yet, so this run uses no glossary and the check never fires. It is covered by unit tests with a small fixture glossary; calibrate it on the references once the real glossary is built. Matching is case-sensitive, and the dev set often names objects in lowercase prose (e.g. 'person account' 6 segments vs 'Person Account' 2, 'case' 49 vs 'Case' 27), so expect missed matches rather than false alarms.
- `placeholders` `{0}` and `max_length` (content_type "ui"): the dev set has no UI strings; covered by unit tests only.
